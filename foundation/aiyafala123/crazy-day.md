## 初见 **Markdown**  

### 关于我为什么要学这些？

原因如下：

### 学习基础语法

我先学习了基础的语法

> `# 一级标题`
> `## 二级标题`
> `*斜体文字*`
> `[文字](链接)`
> `![图片说明](图片路径)`
> `- 无序列表`

有意思的是，有序列表不需要按照 1，2，3，4 的顺序去写，问了下 ChatGPT , 意义是方便修改和插入，还挺方便的。

### 学习感悟

我也用 Markown 完成了这篇文章，不得不说，对于技术人员，Markdown 真的是一个伟大的发明，用起来是真的方便。

| 状态 | 优点 |
| :-----: | :------- |
| ✅ | 语法简单、好记 |
| ✅ | 几乎可以用任何文本编辑器打开 |
| ✅ | 0基础就能学，上手简单 |  
| ✅ | 方便记录代码和技术性文本 |

我之前写 Word 文档时，经常要把时间花到调整行间距之类的排版上。用 Markdown 我只要管内容和结构就行，节省了许多时间。（不过复杂的排版还是要用 Word 😊）

### 学习体会

 我学过一点C、C++,随着我更加深入地学习Python，我也更直观的理解了网上对 Python 简洁、易学的说法：

 C++

 ```C++

 #include <iostream>

 int main(){
    int a,b;
    std::cin>>a>>b;
    std::cout<<a+b;
    return 0;
 }

 ```

 Python

 ```Python
 
a=int(input())
b=int(input())
print(a+b)

 ```

可以看到，同样的程序， Python 更容易让人理解每个语句的意义，也不用写头文件、分号这些东西，还是挺方便的。

## 结语

大概就是这些了，虽然内容很短，但也花费了我几个小时的时间。写这篇文章的时候我还有一些感慨，想起小时候的自己：  

当时什么也不懂，电脑出什么问题，就去贴吧、知乎等各种地方寻找解决办法，这个方法不行换另一个，经常要花费一早上时间才能解决这些问题。

而现在，我写这篇文章也在网上查语法，去找 VS Code 上出现的一些问题的解决办法，找教程配环境。仿佛像是回到了小时候。变的是问题，不变的是“不懂就搜，不断试错”的毅力。

而现在，当身边不懂电脑的朋友遇到问题时，我也能试着帮他们搜一搜，甚至直接帮他们解决问题。虽然算不上什么高手，但至少也不是无能为力。我还挺感谢小时候的自己，虽然什么也不懂，但也培养了我的求知欲。

这或许就是成长的必经之路吧，乔布斯曾说过：

> Stay hungry, stay foolish.[^1]

[^1]: 保持求知若渴、虚心若愚

我相信，即使是个小白，只要一直保持这种探索的好奇心，就一定能走到更远的地方！
