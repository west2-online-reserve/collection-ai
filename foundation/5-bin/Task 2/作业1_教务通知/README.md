# 作业 1：福州大学教务通知采集

使用 Requests 和 lxml 分页采集通知人、标题、日期、正文及附件信息，通过 AJAX 接口获取附件下载次数。支持去重、限速重试、增量保存和实时进度输出。

## 运行

进入本目录，在已激活的 Python 3 虚拟环境中执行：

```bash
python -m pip install -r requirements.txt
python crawl.py
```

当前 `main()` 设置 `max_pages=50`：先收集最多 50 页列表，再逐条处理通知详情和附件次数。可修改该参数调整页数；页数上限不等于成功条数，也不会在成功 500 条时自动停止。

## 输出文件

- `data/notices.csv`：通知人、标题、日期、详情链接、正文，对应 `publisher`、`title`、`published_date`、`notice_url`、`body`。
- `data/attachments.csv`：通知链接、附件名、下载次数、附件编号、下载地址，对应 `notice_url`、`attachment_name`、`download_count`、`attachment_code`、`attachment_url`；通过 `notice_url` 关联通知表。
- `data/state.json`：保存通知、附件及响应依据，作为重启恢复来源。
- `data/errors.csv`：本轮错误的 URL、尝试次数、异常类型及信息，正常结束时覆盖写入。
- `raw/`：原始 HTML、次数 JSON 及带采集时间的响应元数据。

提交三份 CSV 作为采集结果；`state.json`、`raw/` 和临时文件保留本地，由 Git 忽略。

## 进度与恢复

终端实时显示列表页进度、通知序号和标题、附件次数获取或跳过、重试提示及成功/失败累计数。每次请求前等待 1 秒，超时设为 10 秒；超时或连接失败最多尝试 3 次，HTTP 错误直接记录。

重启后读取 `state.json` 并重建两张数据表，复用已保存正文，跳过已知次数，继续补齐未知次数；再次遇到失败通知时重新尝试。每次仍从首页遍历列表，下一列表地址仅打印，不自动保存分页位置。无附件不生成附件行，未知次数留空，真实零次保留为 `0`。
