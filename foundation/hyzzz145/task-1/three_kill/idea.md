# 三国杀游戏设计构思
- 这是一个基于 4 个身份进行的游戏
- 对于 python，我决定整一个 1 个真人 vs 3 个人机的游戏
- 对于英雄系统
    - 我会创造一个 character 类，往下细分 name 类，对于不同英雄会有不同 skill，hp，等等
    - 好像英雄技能不是个简单事
        - 只能把技能分为几个类型
        - 卡牌转换（可以把某种特定牌复制副本给其转换类型的牌，需要有个函数在，每次摸牌后更新其牌组）
        - 规则修改（得单独设计阶段）
        - 阶段跳过（使用 break，或者 赋值）
        - 状态标记（对有某状态标记需求的玩家，进行单独函数设计）
        - 主动技能（在准备阶段，提前提供选项）
        - 事件监听（监听特定事件，放在状态更新函数里）
        
- 牌组系统
    - 我先创造一个 card 类，往下我创造 basic，trick，equipment
        - 对于 trick，我将给他 act_time 的属性 
        - 对于equipment，我给他
        - 对于牌属性会添加类型（保命，进攻；用于人机的出牌判断）
- 玩家系统
    - 一个玩家，要有 hp，（basic，trick，equipment）card_list，attack_distance，濒死，死亡（如果在濒死，没人喂桃，则使其死亡），is_computer，装备区，判定区，是否跳过下回合
- 人机 ai 系统
    - 人机会根据自己的身份判定是否要给濒死的主公喂桃
    - 装备牌，锦囊，和基础牌根据自己生命值打出，若无法根据生命值则随机打出
- 游戏系统
    - 游戏要按照玩家序号循环，
    - 要有以下属性
        - 身份组
        - 玩家组（只记存活的）
        - 牌组（再慢慢减少）
        - 弃牌堆
    - 要有以下函数
        - 扣血
        - 随机抽身份（即使用 random.shuffle 把身份组搞乱，然后按 0-3 的角标给玩家的身份属性赋值）
        - 检查牌组函数（用于查看 len(牌组) 是否小于等于0，若是，则让牌组 copy 弃牌堆并洗牌，然后 clear 弃牌堆）
        - 抽卡（此函数原理是 给玩家 card_list 赋值为牌组[0],并且同时 pop 脚标 0，最后要运行检查函数）
        - 扣血（扣除玩家 hp，需要伤害，进攻方，被进攻方）
        - 弃牌 
            - 随机弃牌
            - 自选弃牌
                - 分为玩家和人机，人机则继续采用随机
        - 强制出杀（要有双方信息，效果）（先检验玩家牌组是否有特定杀，若有，则安排其进行自选，人机默认出，若无，则进行效果）
        - 强制出闪（同上）
        - 强制喂桃
        - 状态更新函数（要判定是否存活），更新玩家列表，只保留存活玩家加入每个阶段后面
- 输赢的判定
    - 如果 player_identify 为某某某，则其他身份某某某死没死来决定，我命名这个函数为【进程判定】，并在那6个阶段的末尾都加入这个函数；或者玩家死亡
