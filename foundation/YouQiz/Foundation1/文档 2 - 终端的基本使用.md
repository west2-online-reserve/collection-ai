# 1.作业中常见的终端相关问题与解决方案

## 1.1 相对路径导致的 “文件找不到” 错误
**现象**：编写读取本地数据文件（如 txt、csv）的代码时，在 IDE 中点击运行可正常读取文件；但手动打开终端执行程序时，报错`FileNotFoundError`（Python）或`No such file or directory`（C++）；在不同目录下执行同一程序，结果也不一致。
**原因分析**：代码中使用了**相对路径**定位文件，而相对路径的基准是终端的**当前工作目录**，而非程序文件本身所在的目录。在不同路径下打开终端，工作目录不同，相对路径的寻址结果就会出错。
**解决方案**：
- 执行程序前，先通过`cd 程序所在目录`令切换到程序文件的父目录，再执行运行命令。
- 代码中使用基于程序文件的绝对路径：例如 Python 中通过`os.path.dirname(os.path.abspath(__file__))`获取脚本所在目录，再拼接目标文件名，彻底规避工作目录的影响。

## 1.2 终端输出中文乱码
**现象**：程序中的中文输出在终端中显示为乱码、问号或特殊符号。
**原因分析**：终端的字符编码与程序的输出编码不匹配，Ubuntu 系统默认字符编码为 UTF-8，若程序输出使用 GBK 等其他编码，或终端 locale 配置异常，就会出现乱码。
**解决方案**：
- 终端执行`export LANG=en_US.UTF-8`临时设置字符编码为 UTF-8，也可修改系统配置永久生效。
- 修改代码，将输出编码统一设置为 UTF-8，与系统终端编码保持一致。


# 2. PyCharm 右上角运行按钮

**显示前提**：右上角的绿色三角形按钮需要关联运行配置（Run Configuration），首次运行可右键代码文件选择 “运行” 自动生成配置，也可手动新建配置。
**底层执行流程**：
  1. 读取当前选中的运行配置，包含脚本路径、Python 解释器、工作目录、命令行参数、自定义环境变量等全部设置。
  2. 拼接完整的执行命令，同时注入 PyCharm 的运行辅助组件（用于调试通信、输出捕获）。
  3. 在 PyCharm 内置的 Run 面板中执行命令，捕获程序的输出流、错误流，格式化后展示在界面上，同时支持运行历史记录。
  4. 调试模式下，会额外启动调试服务，支持断点、单步执行、变量查看等调试功能
