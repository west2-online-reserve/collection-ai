## 1. 路径与目录

### 1.1 不知道自己在哪

常见错误
打开终端就敲命令，不看当前目录。

正确做法
先确认位置，再操作。

```bash
pwd
ls
```

说明
删除、移动、git 操作前尤其要先确认。

---

### 1.2 相对路径和绝对路径混用

常见错误
以为任何地方都能用同一个路径。

结果
提示 No such file or directory。

正确做法
绝对路径以斜杠开头。

```bash
/home/alice/projects/app.py
```

相对路径从当前目录开始。

```bash
projects/app.py
./app.py
../app.py
```

说明
一个点表示当前目录。

说明
两个点表示上一级目录。

---

### 1.3 路径带空格没加引号

常见错误
直接写带空格的名字。

```bash
cd My Documents
```

结果
终端把空格当成参数分隔符。

正确做法
用引号包住，或用反斜杠转义。

```bash
cd "My Documents"
cd My\ Documents
```

---

### 1.4 不在仓库目录就执行 git

常见错误
在任意目录执行 git 命令。

结果
提示 not a git repository。

正确做法
先进入仓库根目录。

```bash
cd ~/projects/my-repo
git status
```

说明
用 ls -a 能看到 .git 目录，通常就是仓库根目录。

```bash
ls -a
```

## 2. 文件操作

### 2.1 以为 rm 有回收站

常见错误
随手删除文件，以为还能找回。

结果
终端删除通常不可恢复。

正确做法
删之前先确认内容。

```bash
ls
rm 文件名
```

说明
删除目录要加 -r。

```bash
rm -r 目录名
```

说明
不要随便加 -f，也不要直接复制网上的 rm -rf 命令。

---

### 2.2 大于号覆盖了重要文件

常见错误
想追加内容，却用了单个大于号。

```bash
echo "hello" > notes.txt
```

结果
原内容被全部覆盖。

正确做法
追加要用两个大于号。

```bash
echo "hello" >> notes.txt
```

说明
单个大于号是覆盖写。

说明
两个大于号是追加写。

---

### 2.3 cp 和 mv 用反

常见错误
想复制，结果用了 mv，原文件消失。

正确做法
cp 是复制，原文件保留。

```bash
cp 源 目标
```

mv 是移动或重命名。

```bash
mv 源 目标
```

## 3. 权限与 sudo

### 3.1 什么都用 sudo

常见错误
一遇到权限问题就加 sudo。

结果
可能改坏系统文件，或让项目文件属主变成 root。

正确做法
先读错误信息，确认是否真的需要管理员权限。

说明
项目文件一般不需要 sudo。

说明
安装系统软件、修改系统配置才需要。

---

### 3.2 不理解 Permission denied

常见错误
看到权限错误就以为命令写错了。

正确做法
先分清读、写、执行三种权限。

```bash
ls -l
```

说明
输出最前面一串字母就是权限信息。

说明
脚本有执行权限但第一行没写解释器也会报错。

```bash
#!/usr/bin/env bash
echo "hello"
```

```bash
chmod +x script.sh
./script.sh
```

## 4. 命令使用

### 4.1 命令拼写错误

常见错误
把 ls 写成 sl，把 cd 写成 dc。

结果
提示 command not found。

正确做法
用 Tab 补全，或用 history 找回旧命令。

```bash
history
```

---

### 4.2 忘了命令有子命令

常见错误
把 git 当单条命令用。

```bash
git file.txt
```

结果
提示不是 git 命令。

正确做法
git 后面先写子命令。

```bash
git add file.txt
git commit -m "说明"
git push
```

说明
docker、npm、pip 等工具也常用子命令。

---

### 4.3 不读错误信息

常见错误
一报错就乱敲，不看终端说了什么。

正确做法
先读最后几行。

说明
命令不存在，多半是拼写或没安装。

说明
文件不存在，多半是路径写错。

说明
权限不足，先检查权限或用 sudo。

## 5. 通配符与管道

### 5.1 不预览星号就删除

常见错误
直接执行带星号的删除命令。

```bash
rm *.txt
```

结果
可能删掉比预期更多的文件。

正确做法
先用 ls 预览匹配结果。

```bash
ls *.txt
```

说明
确认无误后再删除或移动。

说明
不希望星号被展开时，可以加引号。

```bash
echo "*.txt"
```

---

### 5.2 管道方向写反

常见错误
把文件放在管道左边。

```bash
文件.txt | grep 关键词
```

正确做法
管道左边是命令，右边是处理命令。

```bash
cat 文件.txt | grep 关键词
```

更简洁的写法。

```bash
grep 关键词 文件.txt
```

说明
需要时可以把错误输出也重定向。

```bash
命令 > out.txt 2>&1
```

说明
sudo 只对紧跟其后的命令生效，不会影响整条管道。

## 6. 环境变量

### 6.1 命令安装了却提示找不到

常见错误
安装完工具后直接敲命令，提示 command not found。

原因
可执行文件所在目录不在 PATH 里。

正确做法
先确认命令位置。

```bash
which 命令名
```

临时加入 PATH。

```bash
export PATH="$PATH:/新目录路径"
```

说明
这种修改只在当前终端会话有效。

---

### 6.2 PATH 被覆盖导致命令全部失效

常见错误
直接把 PATH 改成新值。

```bash
export PATH="/新目录"
```

结果
系统可能找不到 ls、cd 等基础命令。

正确做法
在原有 PATH 后面追加。

```bash
export PATH="$PATH:/新目录"
```

说明
永久生效要写进配置文件。

```bash
~/.bashrc
~/.zshrc
```

改完重新加载。

```bash
source ~/.bashrc
```

## 7. 好习惯

危险操作前先确认位置和内容。

```bash
pwd
ls
```

用 Tab 补全代替手敲，减少大小写和拼写错误。

不熟悉命令时先看帮助。

```bash
命令 --help
man 命令
```

用 history 或 Ctrl + R 找回旧命令。

命令卡住时先按 Ctrl + C 中断。

重要文件操作前先备份。

```bash
cp 重要文件 重要文件.bak
```

说明
终端删除通常不可恢复。

---

## 8. 学习总结

通过练习，我学会了用 pwd 确认当前位置、用 cd 切换目录、分清相对路径和绝对路径。

也知道了 rm 没有回收站、单个大于号会覆盖文件、cp 和 mv 的区别。

遇到 Permission denied 和 command not found 时，不再盲目乱敲，而是先读错误信息，再判断是路径、权限还是拼写问题。

我还学会了用 Tab 补全减少手误，用 history 和 Ctrl + R 找回旧命令，用 Ctrl + C 中断卡住的命令，以及重要操作前先备份。

终端不仅能运行程序，也能帮助我们更安全、更高效地调试代码和管理文件。
