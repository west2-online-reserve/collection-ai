# 我的第一份 Markdown

## 一、为什么我要学 Markdown

我决定从第一份 Markdown 开始，练习标题、图片、链接、代码块和表格这 5 种常见元素。

## 二、准备 GitHub 账号和仓库

我先注册了一个 GitHub 账号。创建完成后，我打开 VS Code，准备在本地写第一个文件。

## 三、创建 crazy-day.md

我在仓库根目录新建了一个文件，文件名是 crazy-day.md。这个文件用来记录我学习 Markdown 的过程。

## 四、我练习的五种元素

### 多级标题

我打算用三级标题来组织文章。文章总标题用一级标题，大节用二级标题，小节用三级标题。这样转换后层级清楚，也不会跳级。

### 图片插入

### 链接插入

### 代码块

```python
print("hello,world")
```

### 表格

下面是一个 Markdown 语法对照表：

| 语法 | Markdown 写法 | 用途 |
|:-----|:--------------|:-----|
| 标题 | `# 标题文字` | 创建一级标题 |
| 链接 | `[文字](网址)` | 插入可点击链接 |
| 代码块 | `` ``` `` | 包裹代码并保留格式 |


## 五、检查 Apple 中文排版规范

写完以后，我重点检查了排版。中英文之间要加空格，例如“打开 VS Code，然后点击设置”。中文与数字之间要加空格，例如“我练习了 5 种元素”。数字与单位之间不加空格，例如“文件大小只有 10MB”。中文语境使用全角标点，例如逗号、句号和问号；英文和代码语境使用半角标点。这样读起来更舒服，也更容易通过 Markdown Lint 的基本检查。

## 六、提交到 GitHub

最后，我使用 Git 把 crazy-day.md 提交到仓库。命令很简单：先 git add crazy-day.md，再 git commit -m "add crazy-day.md"，最后 git push。提交成功后，我在 GitHub 页面上看到了渲染后的文章，标题、图片、链接、代码块和表格都显示正常。

## 七、小结

第一份 Markdown 让我明白，写作规范不只是形式问题。中英文空格、数字空格和全角标点，都会影响文章的可读性。下一步我准备继续学习 Git 分支和 Pull Request，把更多学习笔记整理成 Markdown 文档。
