## 数据类型

python 中的特殊数据类型有 list 列表, tuple 元组, dict 字典, set 集合

list: []经常用于存储元素或者增删操作，通过下表就能访问元素，检索元素较方便

tuple: ()用于处理不再变化的数据。和 list 的区别--元组不能修改元素值、不能进行增删操作，也不能改变元素排列顺序

dict: {}/dict([(),()]) 键值对，通过键访问值，用于数据量相当大的查找功能，因为数据量很大时，使用 list 不一定能确定具体的下标是什么

set: {}/set([]), 存入的元素无序，并且重复元素只保留一次，可以用来删除重复元素，元素可以被更改，也支持两个集合中对应元素的运算。由于类型使用的括号和字典一样，如果创建空集合，必须使用 set()

## Lambda 匿名函数

没有名字的轻量函数，只能包含一个表达式，不能写语句，表达式的值就是返回值，适合逻辑简单的场景

#### 语法

```bash
lambda 参数1, 参数2, ...: 表达式

example:
def add(x, y): return x + y
add = lambda x, y: x + y    # 二者等价
```

因为轻量，且必须返回值，**经常用于减少代码行**

#### 常用用法

```bash
sorted(list, key = lambda w: w.lower()) # 如果 list 包含的是字符串元素，那么该行可用于忽略大小写排序
sorted(list, key = lambda w: len(w)) # 用于按照长度给列表排序
# 也可以用于字典中的键，从而获取相应的值

list(map(lambda x: x**2, [1, 2, 3]))            # [1, 4, 9]
list(filter(lambda x: x > 0, [-1, 0, 1, 2]))    # [1, 2]

from functools import reduce
reduce(lambda a, b: a + b, [1, 2, 3, 4])        # 10
```

## Decorator 装饰器

装饰器是接收函数、返回新韩淑的高阶函数，可以把原函数“包裹”起来，然后往这个包裹里丢一些方法运行，不改变原函数，但是“扩充”原函数的功能

```bash
def decorator(func):
    def wrapper(*args, **kwargs):
        # 前置操作
        result = func(*args, **kwargs)
        #后置操作
        return result
    return wrapper
    
@decorator
def my_func():
    ...
```

例子:
```bash
import time
from functools import wraps

def timer(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)   # 原函数执行
        cost = time.perf_counter() - start
        print(f"{func.__name__} 耗时 {cost:.4f} s")
        return result    # 必须返回
    return wrapper       # 必须返回
    
@timer    # 加上以后相当于把 slow_sum() 当作形参 func 传入装饰器
def slow_sum(n):
    return sum(range(n))
```

类装饰器
```bash
@staticmethod	变成静态方法，无 self/cls(类对象)
@classmethod	第一个参数是 cls，可访问类属性、做替代构造器
@property	把方法变成属性访问，配合 .setter / .deleter
```


## 类

类属性：定义在类体中，所有实例共享，通过给实例赋值会新建实例属性，或者说覆盖

实例属性：在 `__init__` 或者方法中通过 self. 创建，存在于 `__dict__`

类属性可以用类名访问也可以用对象名访问，类似其它语言的静态属性，不同点在于，静态属性改变的对象永远只是一个，而 python 中用对象名改变类属性值，会建立一个新的覆盖，而不是在原基础上进行覆盖

方法类型：可以理解为函数，但是函数是通用的，而面向对象中一般称作方法，分为实例方法，类方法，静态方法

### 类的三大特性

**封装**：隐藏内部状态，暴露接口。比如手机隐藏了内部组成，只给你留一个屏幕，你通过屏幕操作手机

**继承**：用于复用和扩展代码，即不要重复造轮子

**多态**：同一个接口不同的实现，通常是派生类重写了父类的方法

`__init__`: 初始化已创建实例，返回值必须为 None

`__new__`: 创建实例，先于 `__init__` 执行

#### Magic Methods

**前后双下划线**包裹、解释器隐式调用的特殊方法，可以理解为每个类的默认装配属性，比如 __init__ 就是默认的构造方法体。理解起来就是，Python 已经提前给你造了好多类方法，比如什么运算，构造初始化，输出等等，通过这类工程化的默认方法，你就不用自己花费太多精力创造方法，除非你发现默认方法满足不了你的需求。这也是面向对象的优势，你可以套用已有的方法甚至扩展它们，只要你想。不是说非得用这些方法，只是写出来看上去会更系统化工程化，换句话说，更容易理解

有很多不同的魔法方法，上网搜索如下：

```bash
class Res:
    def __new__(cls):  print("new");  return super().__new__(cls)
    def __init__(self): print("init")
    def __del__(self):  print("del")   # 不保证及时调用，别依赖它释放资源
    
class P:
    def __init__(self, x, y): self.x, self.y = x, y
    def __repr__(self):  return f"P({self.x}, {self.y})"   # 开发者调试，应可重建
    def __str__(self):   return f"({self.x}, {self.y})"    # 用户展示，print 优先
    def __format__(self, spec): return f"x={self.x:{spec}}"
    
class Vec:
    def __init__(self, x): self.x = x
    def __add__(self, o): return Vec(self.x + o.x)     # a + b
    def __radd__(self, o): return self.__add__(o)      # o + a（o 不支持时）
    def __iadd__(self, o): self.x += o.x; return self  # a += b
    def __mul__(self, k): return Vec(self.x * k)
    def __neg__(self): return Vec(-self.x)             # -a
#等等
```

## 面向对象编程思想

将数据和操作数据的方法(不理解就视为函数)深度绑定起来，这些数据和方法都是独立的，只属于某个对象。各个对象之间相互协同，共同完成系统功能。

什么叫**数据和方法深度绑定**？好比班上每个人有一本笔记本，用于记录学习笔记。那么每一份学习笔记是不是就和那本笔记本绑定了，当你想要复习时，你得通过打开笔记本获取你的笔记。笔记本就是方法，笔记就是数据，从这个例子也可以看出，笔记本(方法)是访问笔记(数据)的接口

什么叫**数据和方法独属于对象**？ 你自己的笔记本和笔记只属于你，总不能属于别人吧

什么叫**各个对象之间相互协同**，共同完成系统任务？ 马上期末了，期末就要进行考试，那么地球 online 的系统任务就是期末考试。为了考出好成绩，你和同桌决定互相分享笔记，彼此弥补自己遗漏的知识点。那么你需要允许你的同桌访问你的笔记本(方法)，通过你的笔记本访问你的笔记(数据)。你访问同桌笔记的方式一样。那么你们相互补充、相互协同，最后共同完成“期末考试”这个系统任务。

## 面向对象的设计意图

### 封装

隐藏内部细节，只暴露部分方法，**外界不依赖实现细节**。

你通过自己的学习方法取得了好成绩，当外界询问你是怎么做到的，你不可能全盘脱出，你的分享可能只有“多记笔记”之类的，而不是你学习方法的全部。外界不需要知道你是怎么努力的，只需要知道你取得了好成绩

### 抽象

从复杂实现中**提炼出共性**，屏蔽细节

人人都说努力才能通向成功，这里的“努力”就是一个抽象，因为它并没有指出具体应该怎么做，怎么“努力”

### 继承

**复用**已有实现，表达类型，容易被滥用

每个人对努力的理解不同，也不知道努力的细节是什么，他们能做的就是在“努力”的基础上，各自摸索出一条自己的“努力”的方法。

容易被滥用？ 有的人对努力的理解可能是让别人看到自己在发力，于是出现了假努力，何尝不是对努力的滥用，还吃力不讨好

### 多态

**用统一接口处理不同实现**

继承侧重的是别人在“努力”的基础上这个情况

多态侧重的是每个人建立自己的“努力”方法，从而产生不同的分支结果，比如有的人记笔记、有的人刷题、有的人二者兼具

## 类的设计原则

**SOLID 五原则**

1. S 单一职责：一个类只干一件事

2. O 开闭： 扩展应该靠增加代码而不是修改代码

3. L 里氏替换： 子类不要破坏父类的方法哲学

4. I 接口隔离：不要要求方法实现类实现自己本来实现不了的方法。比如你写一个宝可梦回合战斗项目，你的设计者哲学是角色、技能、属性分离，而属性只作用角色不作用技能，你非得在属性里搞一个技能的属性加成，那么 bug 一定会攻击你

5. D 以来配置： 最高层的一些父类的方法应该是抽象的，而不是具体的，有助于派生类自己实现自己的独特的方法


## re 正则表达式

re 是正则表达式模块，用来做字符串的匹配、查找、替换、分割操作，核心是“用 pattern 描述字符串”

毕竟可读性相当差，正则的一般使用场景主要有以下几种：

1. 模式有规律但无法用固定字符串描述（比如"任意 3 个数字 + 一个横杠 + 任意 2 个字母"）；

2. 需要反复对大量文本做同样的提取/校验/替换；

3. 字符串方法（split / startswith / replace / isdigit）确实表达不了。

基本函数
```bash
import re

# 1. 查找：返回第一个匹配对象，找不到返回 None
m = re.search(r"\d+", "abc123def")
if m:
    print(m.group())      # "123"

# 2. 匹配开头：只从字符串开头匹配
re.match(r"\d+", "123abc")   # 匹配成功
re.match(r"\d+", "abc123")   # None

# 3. 查找全部：返回所有匹配的列表
re.findall(r"\d+", "a1b22c333")   # ['1', '22', '333']

# 4. 替换
re.sub(r"\d+", "#", "a1b22c333")  # 'a#b#c#'
```

## 推导式(四种推导式，逐一讲解)

**注**：都是返回新对象，而不是修改原来的对象

#### 骨架

```bash
[表达式 for 变量 in 可迭代对象 if 条件]      # 列表
{键: 值 for 变量 in 可迭代对象 if 条件}      # 字典
{表达式 for 变量 in 可迭代对象 if 条件}      # 集合
(表达式 for 变量 in 可迭代对象 if 条件)      # 生成器
```

### 列表推导式

从可迭代对象生成一个新列表，遍历、筛选、转换全在一行代码里，立即执行，结果完整存入内存

但是生成新列表，而不是原地修改列表，只能写一个语句

#### 简单例子
```bash
[x if x > 0 else 0 for x in [-1, 2, -3]]    # [0, 2, 0]
```

### 字典推导式

从可迭代对象生成一个新字典，必须写键: 值的形式，即冒号不能省去，否则就变为集合，键必须可哈希，重复键后者覆盖前者

#### 简单例子
```bash
original = {"a": 1, "b": 2}
{v: k for k, v in original.items()}     # {1: 'a', 2: 'b'}
```

### 集合推导式

从可迭代对象生成一个新集合，自动去重，无序，可哈希

#### 简单例子
```bash
words = ["apple", "banana", "apple", "cherry"]
{w for w in words}                      # {'apple', 'banana', 'cherry'}
```

### 生成器表达式

返回一个生成器对象，惰性求值--不立刻计算，而是需要时才进行计算，不会占用大量内存

所谓**惰性**：比如你需要用到一个列表的元素，且是顺序使用，如果直接存入一个列表进去，那么大部分时候可能你没有用到列表元素，仍然占用空间。通过惰性，只有你需要的时候生成一个元素，然后用完即弃，每次最多只有一个元素会占用空间

本质是**迭代器**，靠指针往前走，所以用完如果指向了下一个，那么当前这个就被丢弃了无法再要回来了

#### 简单例子
```bash
gen = (x ** 2 for x in range(5))
print(gen)              # <generator object ...>
list(gen)               # [0, 1, 4, 9, 16]
list(gen)               # []   ← 只能遍历一次！

gen = (x ** 2 for x in range(5))

next(gen)        # 这时才算第 1 个 → 0
next(gen)        # 这时才算第 2 个 → 1
list(gen)        # 这时才把剩下的全算完 → [4, 9, 16]
```


|列表推导式|	字典推导式|	集合推导式	|生成器表达式|
|:---:|:---:|:---:|:---:|
|语法|	[...]|	{k: v ...}|	{...}	|(...)|
|返回|	list|	dict|	set|	生成器对象|
|执行时机	|立即|	立即	|立即|	惰性|
|内存	|全部加载	|全部加载	|全部加载	|几乎不占|
|可重复遍历	|✅|	✅|	✅|	❌ 只能一次|
|可索引	✅	|按键|	❌| 无序|	❌|
|自动去重	|❌	|键去重|	✅|	❌|
|典型场景	|转换/过滤列表	|建映射/反转|	去重|	大数据/聚合|

## Generator 生成器(yield 关键字)

普通函数遇到 return 就结束，但是生成器函数使用 yield 产出一个值，然后标记这个位置，下一次执行这个函数就从这个位置开始执行

**主要用途**：防止内存爆炸，比如处理一些超大文件或者无限的数据，如果一次性读入但是没有清理，那么内存极容易占满，通过 yield，不仅可以实现需要哪里得到哪里，还能用完即弃，一次最多只占用一小块内存，和惰性差不多

**注意**：只要函数体里有 yield 关键字，那么这个函数就不再是普通的函数，调用它不会执行函数体，而是返回一个生成器对象

### 例子
```bash
def count_up(n: int):
    for i in range(n):
        yield i          # 产出 i，然后暂停

gen = count_up(3)      # 返回的是生成器对象
print(gen)               # <generator object count_up at ...>
print(next(gen))         # 0  ← 执行到 yield 0，暂停
print(next(gen))         # 1  ← 从暂停处继续，到 yield 1，暂停
print(next(gen))         # 2
print(next(gen))         # StopIteration
```

### 文件处理
```bash
def read_lines(path: str):
    with open(path, encoding="utf-8") as f:
        for line in f:
            yield line.strip()

for line in read_lines("huge.txt"):
    process(line)     # 一次只加载一行,避免大文件占用大量内存
```

|	|return|	yield|
|:---:|:---:|:---:|
|执行次数	|一次，函数结束	|多次，每次暂停|
|返回值|	单个值	|每次产出一个值|
|函数状态	|结束即销毁	|暂停时保留局部变量和执行位置|
|调用结果	|直接得到值	|得到生成器对象，需 next() / for 消费|


### 对比生成器表达式

生成器表达式都是很简单的表达式，只有一行的同时表达式数量相当有限。使用了 yield,你就可以跳出一行代码的局限，拥抱逻辑更复杂的方法，还能保留相应的状态，不需要重复执行方法，也不需要重复生成占空间的数据。不用万事俱备，而是麻雀虽小五脏俱全。

## python 的对象

对象分为不可变对象和可变对象

### 对于不可变对象而言

“赋值”的本质是创建新对象，给变量使用，变量指向了对象的地址，因此可以知道该地址对应的值。当用该变量给另一个变量“赋值”时，其实是让那个新变量指向了这个地址，因此那个变量也可以获取值。当改变这个新变量的值，本质是让这个变量指向一个新的地址，而不是修改原先指向的地址的值，看上去像是赋值，其实是每个地址的值是不可变的，变量获取值的方法是通过指向值的地址而不是改变值本身

不可变对象就是一些普通数据类型，如 int, str 等

```bash
b = 10
a = b
a = 5
print(a) # 5
print(b) # 10
```

### 对于可变对象而言

“赋值”的本质是对原对象的引用，因此变量之间会相互影响，因为它们是同一个对象的不同引用

可变对象是一些特殊数据类型，如 list/dict/set 以及用户自己编写的类对象(可以人为冻结为不可变)等

```bash
b = [1, 2, 3]
a = b
a[1] = 4
print(a) #[1, 4, 3]
print(b) #[1, 4, 3]
```
```bash
class People:
     ……
p1 = People("jack")
p2 = p1
p2.name = "lili"
print(p2) #lili
print(p1) #lili
```

两个对象的值可以完全相同，但是它们终究是两个不同的对象
```bash
class Num:
    def __init__(self, num):
       self.num = num
       
u1 = Num(1)
u2 = Num(1)
print(u1 == u2) # True 内容相同
print(u1 is u2) # False 是两个不同对象 
```

这点很重要，尤其是传入形参数据时,比如你宝可梦里角色和技能分离，要给角色赋予技能，但是技能状态实时变化，你使用了一个方法输出技能状态
```bash
class 技能:
    此处省略
    
class 宝可梦：
    宝可梦.add(技能)
    宝可梦.get(技能)
    
def 输出技能状态(技能):
    print(技能状态)
    
baokemeng = 宝可梦(技能a)

输出技能状态(baokemeng.get(技能))  # 那么会输出相应技能实时状态

# 但如果你嫌麻烦，直接传入一个对象
输出技能状态(宝可梦(技能b).get(技能)) # 输出一个孤立的技能状态
# 即便你的技能 b 和技能 a 同一种技能，它们已经是不同的对象了,状态完全不同
```
给的例子可能不够有说服力，可以去看看同一文件夹下编写的宝可梦项目，里面的逻辑复杂，类之间总是相互传递对象，为了避免无关对象传入，因此我在基类里加入了好多不适用于所有派生类的属性
